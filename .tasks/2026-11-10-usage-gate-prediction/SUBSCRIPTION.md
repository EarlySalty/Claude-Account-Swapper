# Subscription freshness

Root cause:
1. Mechanism: web_snapshot displays Profile.subscription_type, populated by save_live_as at login. The screenshot shows that saved Max label alongside usage older than 1,000 minutes.
2. Why possible: parse_live_account reads email and organization only, discarding subscription entitlement. Usage-cache fallback has no independent subscription eligibility check.
3. Why unnoticed: the panel reports a stored account without a subscription verification state, and stale usage still feeds its bars and weekly pacing text.
4. Twins: web, list/status labels, cached candidates, manual pins, automatic switching and inactive pings share the same saved metadata or cached usage. Confirmed inactive subscriptions must not fall back to those measurements.

Contract: fetch the existing profile endpoint at most once per ten minutes per quota under the shared usage lock. Persist only nonsecret verification state. Unknown fields and transient errors do not establish an inactive subscription. Explicit free organization or missing paid entitlement establishes inactivity; canceled billing alone with paid entitlement does not establish lost access. Check identity before applying a response. Never re-date usage when checking entitlement. Confirmed inactive state persists until a positive verification replaces it. Stale or missing positive verification is displayed as unverified. Old bars are hidden after 30 minutes, even when recovery logic retains historical readings as a last resort. Inactive accounts are excluded from cached candidates and can trigger recovery when active, before manual-pin handling.

New fields and readers: UsageGate.subscription is optional for old stores; null or absent means unverified. Its checked_at must not be in the future; positive state expires for display after one hour, and negative state remains protective until a positive check. subscription_retry_at defaults to zero and is reserved before a network call under the shared lock. Values beyond the maximum reasonable retry window cannot suppress checks forever. LiveAccount.subscription is absent for unknown fields, so identity resolution still works without asserting a plan. Web subscriptionInactive is a boolean, subscriptionType is display text, subscriptionCheckedAt is optional numeric time. Old frontends ignore these added fields; the changed frontend accepts absent subscriptionInactive as false. Profile errors remain visible and cannot restore stale access. Unknown organization is matched strictly rather than applying another organization's entitlement.

Tests: the mocked no-subscription account has the screenshot's old 0%/11% readings. Repeated usage requests verify that it never reaches the usage endpoint, that profile requests are deduplicated, that it cannot be selected by checked switch and that auto recovery chooses the other account. The dashboard regression verifies that the saved Max label and old bars are absent. Parsing fixtures cover expired, past-due, free, paid Pro, active canceled Max, Team and missing or malformed flags. The profile request's completion time is re-read before applying its verified result.

Browser verification: Moli rendered the real app.js and style.css with synthetic backend data, without a server or a personal browser. The inactive card has no buttons or usage bars, and is absent from the quick-switch options. Unknown status shows Abo ungeprüft separately. The rendered fixture is /tmp/cas-subscription-qa/panel.png. A file-URL attempt required a capability not exposed by the CLI; an inline data document provided the same isolated verification in Moli without granting file access or changing browsers.

The user-requested gate retry started against c3bd0fa before this additional bug was implemented. No gate verdict for this subscription change is claimed. No subscription patch has been deployed yet. Production status was verified as Pro 2003 during this work.

Verification: cargo-slot test --quiet passed 116 library tests and 110 CLI tests. Clippy with warnings denied, formatting and diff whitespace checks passed. Moli DOM checks verified two account card states and that the inactive account is excluded from quick-switch choices. The screenshot was visually inspected. No production model calls were made for these tests; the separate required review uses the configured reviewer chain.
