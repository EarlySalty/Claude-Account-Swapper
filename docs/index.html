Claude Account Swapper für Linux

Doppelklick. Account wählen. Fertig.

Der Desktop-Starter öffnet ein einfaches Terminalmenü. Dort lassen sich Claude-Code-Accounts speichern, einmalig anmelden und danach ohne erneuten Browser-Flow wechseln.

01 SpeichernDen aktuellen Claude-Login einmal benennen.
02 AnmeldenJeden weiteren Account genau einmal offiziell autorisieren.
03 WechselnDanach per Name oder interaktiv in Sekunden umschalten.

Installation

git clone https://github.com/EarlySalty/Claude-Account-Swapper.git
cd Claude-Account-Swapper
./install.sh

Der Installer aktualisiert die Binary und legt Claude Account Swapper auf dem Desktop sowie im Anwendungsmenü an. Erforderlich sind Linux, Rust 1.88 oder neuer und die offizielle Claude-Code-CLI.

Erste Einrichtung

  1. Claude Account Swapper auf dem Desktop doppelklicken.
  2. Aktuellen Account speichern wählen und einen kurzen Namen eingeben.
  3. Neuen Account anmelden wählen und den offiziellen Browser-Login einmal abschließen.
  4. Danach über Account wechseln direkt umschalten.
[1] Account wechseln
[2] Aktuellen Account speichern
[3] Neuen Account anmelden
[4] Status anzeigen
[5] Beenden

Befehle

BefehlWirkung
save <name>Speichert den aktuell autorisierten Login.
login <name>Fuehrt einmal den offiziellen Claude-Login aus und speichert ihn.
switch <name>Wechselt zum gespeicherten Account. use ist ein Alias.
listListet Profile und markiert den aktiven Account.
statusFragt Claude nach dem tatsaechlich aktiven Login.
claude-accountÖffnet dasselbe Hauptmenü wie der Desktop-Starter.

Was beim Wechsel passiert

  1. Der Switcher fragt claude auth status nach der aktiven Identitaet.
  2. Der aktuelle Inhalt von ~/.claude/.credentials.json wird zum passenden Profil zurueckgesichert.
  3. Das Zielprofil wird validiert und ueber eine temporaere Datei atomar aktiviert.
  4. Der Identitaets-Cache in ~/.claude.json wird geleert; Claude Code laedt ihn beim naechsten Start passend zum neuen Token neu.
  5. Offene Claude-Code-Sessions nutzen den neuen globalen Login bei der naechsten Anfrage.

Warum der Identitaets-Cache geleert wird

.credentials.json enthaelt nur Tokens, keine Kontodaten. Zu welchem Konto der Login gehoert, haelt Claude Code getrennt davon in ~/.claude.json unter oauthAccount und userID. Wird nur die Credential-Datei getauscht, zeigt dieser Cache weiter auf das alte Konto.

Die Folgen waren Login expired · Please run /login in Claude Code und ein Switcher, der die Tokens des neuen Kontos in das Profil des alten zurueckschrieb, weil claude auth status denselben veralteten Cache liest. Der Switcher entfernt darum beide Felder bei jedem Wechsel und laesst alle uebrigen Einstellungen in ~/.claude.json unangetastet.

Sicherheitsmodell

Die gespeicherten Dateien sind aktive OAuth-Geheimnisse.

Sie liegen unter ~/.claude-account-switcher/ mit privaten Dateirechten. Nimm dieses Verzeichnis nicht in Git, Cloud-Sync oder unverschluesselte Backups auf.

Ein unbekannter aktiver Login wird nie verworfen. Ungueltige Zielprofile werden vor jeder Mutation abgelehnt. Abgebrochene oder falsche Browser-Logins rollen auf den vorherigen Credential-Stand zurueck.

Gesetzte Variablen wie ANTHROPIC_API_KEY wuerden die Datei-Auswahl ueberschreiben. Der Switcher erkennt diese Overrides und bricht sichtbar ab.

Grenzen

Das Tool ist absichtlich klein und aktuell Linux-only. Es loest keine serverseitigen OAuth-Fehler und keinen internen Refresh-Token-Race in mehreren Claude-Prozessen. Wechsle idealerweise zwischen zwei Prompts statt waehrend einer laufenden Anfrage.

Eine laufende Claude-Code-Session haelt ~/.claude.json im Speicher und schreibt die Datei beim Beenden komplett zurueck – samt altem Identitaets-Cache. Fuer einen sauberen Wechsel alle offenen Sessions vorher beenden.
