# Local usage coordination

Every usage endpoint call enters one filesystem single-flight lock in the configured account store. Watcher, CLI, web refresh, job checks and post-job confirmation share this path. Both inspected user units run ~/.cargo/bin/claude-account without a store override. Other machines and independently configured stores do not share this budget.

Successful measurements are reused for 180 seconds for the active account and 600 seconds for inactive accounts. Normalized email identifies an account across aliases and token rotation. This deliberately shares the budget across organizations belonging to that email. A new email identity starts cold. Each request has a 10 second HTTP timeout. Failed attempts wait at least 180 seconds per account. A 429 imposes a persisted shared cooldown of 300 seconds, then 600, then up to 900 seconds. Retry-After seconds or HTTP dates can extend that delay without an upper cap. Missing or zero headers cannot shorten the exponential delay. Successful requests clear the consecutive failure counter.

Cache hits retain the original fetched_at. Canonical measurements and cooldowns are atomically persisted with errors propagated. Legacy profile caches remain readable. No credential format or token storage changes are involved. A crashed request leaves its attempt delay in place. Manual refresh cannot bypass the gate. Post-job confirmation waits for another permitted measurement instead of treating the pre-job cache as proof of a new window.

Prediction uses the last two measurements for the same account, matching known future reset windows, and a maximum measurement interval and sample age of 20 minutes. It rejects decreasing values and zero elapsed time. Each eligible window projects its observed slope through sample age, the next 180 second poll and switch lead. Five-hour and weekly windows are considered independently. Product logs distinguish measured percentages, age and projected percentages. Cold history cannot establish a slope.

Defaults are a 5 percentage point reserve and 60 second switch lead. Set CLAUDE_ACCOUNT_SWITCHER_USAGE_RESERVE (0 through 50) and CLAUDE_ACCOUNT_SWITCHER_SWITCH_LEAD_SECONDS (0 through 3600) on all service consumers consistently. Invalid values use defaults. Predictive targets need measurements at most 600 seconds old and twice the configured reserve below their own limits, including their available projection. Aliases of the active account are excluded. Manual pins retain precedence; existing hard limits, weekly pacing and resume protections remain in their existing decision paths.

Sudden jumps can exhaust quota between measurements. Existing hooks expose session identity, lifecycle and transcript paths, but no measured quota fields or confirmed session-limit event in HookInput. This change does not invent an event payload or interpret usage endpoint 429 as exhausted session quota. Existing session parking and resume processing remain intact. Reactive targets also require measurements at most 600 seconds old; stale optimistic targets are excluded.

Verification uses local mock HTTP endpoints and temporary account stores. Tests cover concurrent independent CLI processes, cache age preservation across restart, shared 429 cooldown, alias and token rotation, fast and slow predictions, cold history, reset mismatch, stale samples, repeated samples and no safe predictive target. The harness defaults all usage requests to a closed local endpoint. Independent review and deployment belong to the parent.

Build and deployment remain with the existing cargo-slot wrapper and install.sh. Verification uses cargo-slot test and cargo-slot clippy --all-targets -- -D warnings. The parent must use its approved release/deployment wrapper; this worker does not run cargo install, install.sh, service restart or production switching.

Final verification: 111 library tests and 101 CLI integration tests passed. Clippy with warnings denied, formatting and diff whitespace checks passed. No release build or deployment was performed.
