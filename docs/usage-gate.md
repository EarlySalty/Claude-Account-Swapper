# Local usage coordination

Usage requests enter one filesystem lock in the configured account store. Watcher, CLI, web refresh and job checks reuse the same measurements. Post-run confirmation reads those measurements without making extra requests. Other machines and independently configured stores do not share this budget.

Measurements are reused for 180 seconds for the active account and 600 seconds for inactive accounts. Normalized email and organization identify a quota across aliases and token rotation. Unknown organization is distinct from a known organization. Each request has a 10 second HTTP timeout. Every attempt reserves at least 180 seconds per quota. A 429 imposes a persisted store-wide cooldown of 300 seconds, then 600, then at most 900 seconds. Retry-After seconds or HTTP dates through 24 hours extend that delay. Larger values are logged as invalid and use local backoff. Missing or zero headers cannot shorten it. A successful request clears consecutive failures.

Cache hits retain the measurement timestamp. Canonical state is atomically persisted with errors propagated. Manual refresh cannot bypass the gate. CLI and web readers expose age; the web stale marker includes the refresh interval, watcher tick and normal loop margin.

Subscription eligibility is checked through the existing profile endpoint at most once per ten minutes per quota, under the same process lock. Responses must match the stored email and organization. Explicitly inactive subscriptions cannot use cached quota or become automatic targets; an inactive active account can recover to another usable account before manual-pin handling. A later positive verification restores eligibility. Network errors and unknown entitlement fields do not establish inactivity. The panel uses verified subscription state rather than the login-time plan label, marks unverified state explicitly, and hides usage readings older than 30 minutes. Inactive account cards and quick-switch choices cannot offer a switch back to that account. Billing cancellation with a still-active paid entitlement is distinguished from lost access.

Prediction uses the last two measurements for the same quota and matching future reset windows. Sample spacing and age must each be at most 20 minutes. A valid nonnegative slope projects through sample age, the next polling interval and switch lead. Both five-hour and weekly windows are considered. Expired windows settle to zero. Without usable history, measured utilization plus reserve still applies. Logs distinguish measured values, age and projections.

Defaults are a 5 percentage point reserve and 60 second switch lead. CLAUDE_ACCOUNT_SWITCHER_USAGE_RESERVE accepts 0 through 50; CLAUDE_ACCOUNT_SWITCHER_SWITCH_LEAD_SECONDS accepts 0 through 3600. Invalid values use defaults. Set them consistently for every service consumer. Predictive targets require measurements at most 600 seconds old and twice the reserve below their limits. Weekly pacing uses the same target headroom check; reactive recovery prefers such targets but can use remaining quota or stale measurements as a last resort when no safe target exists. This retains reset recovery during throttling.

Quota protection works immediately after an automatic switch. The three-hour dwell applies only to weekly balancing. For an account with a usable subscription, existing manual pins retain precedence: soft limits hold the selected account until actual exhaustion at 100%; hard limits release the pin at their configured threshold. Prediction does not override a pin. Confirmed loss of subscription releases the account regardless of its pin.

Jobs and pings persist the quota identity and completion time for confirmation. Only a later measurement whose reset could belong to the original five-hour window confirms that run. A newer window is not credited to an older run. Confirmation expires after five hours even without a measurement or remaining profile. Repeating jobs retain their previous window while waiting, with the existing 15-minute rerun gap after release. Pending pings block another ping of the same quota, including aliases. Ping bookkeeping failures are logged without stopping quota protection. Limit-pause forecasts count each quota once and retain the active profile's own limits when aliases exist.

Tests use local mock endpoints and temporary stores for cache reuse, concurrency, cooldowns, aliases and organization separation, prediction and deferred confirmation. No application model requests are required by those tests. Verification uses cargo-slot test, cargo-slot clippy --all-targets -- -D warnings and cargo fmt --check. Release installation uses the existing cargo-slot deploy path after the merge gate allows the release.

Sudden usage jumps can exhaust quota between measurements. The current hook schema provides no confirmed quota-limit event, so the usage endpoint remains the source of measurements. An endpoint 429 is a throttled measurement request and does not prove the session quota was exhausted.
